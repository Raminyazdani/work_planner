# Work Planner

برنامهٔ شخصی ثبت ساعت برای **Jena** و **Seewiesen**: جدول قابل ویرایش، نمای روزانه از ۰۰ تا ۲۴، رسم و جابه‌جایی بازه‌ها، تشخیص هم‌پوشانی و خروجی اکسل جدا برای هر محل کار.

کد این مخزن عمومی است؛ ساعت‌ها، یادداشت‌ها، تقویم و کلیدهای دسترسی داخل مخزن قرار نمی‌گیرند. نصب تازه خالی است. دکمهٔ نمونه فقط دادهٔ آزمایشی مشخص‌شده می‌سازد.

## اجرای محلی روی Windows، macOS یا Linux

پیش‌نیاز: **Node.js 24 LTS** و Git. سپس:

```sh
git clone https://github.com/Raminyazdani/work_planner.git
cd work_planner
npm ci
npm start
```

آدرس [http://127.0.0.1:8765](http://127.0.0.1:8765) را باز کن. پس از نصب اولیه، ویرایش، ذخیره، تشخیص هم‌پوشانی و خروجی اکسل بدون اینترنت کار می‌کنند. دریافت تغییرات Google Calendar به اینترنت نیاز دارد؛ آخرین نسخهٔ دریافت‌شده در اجرای محلی حفظ می‌شود.

برنامهٔ محلی فقط به `127.0.0.1` متصل است. داده‌ها در پوشهٔ خصوصی `.data/` ذخیره می‌شوند. برای تغییر پورت یا محل ذخیره، `.env.example` را به `.env` کپی و ویرایش کن. از قرار دادن `.data/` یا فایل پشتیبان در Git خودداری کن. برای پایان برنامه در ترمینال `Ctrl+C` بزن.

## استفاده و انتقال اطلاعات

- هر ردیف یک بازهٔ کار پیوسته است. استراحت را با دو ردیف جدا ثبت کن؛ گزینهٔ «روز بعد» برای عبور از نیمه‌شب است.
- از جدول یا با کشیدن روی روز موردنظر، بازه بساز. بازه‌ها رنگ جدا دارند و تداخل‌ها مشخص می‌شوند.
- زیر **هر بازه**، کادر «شرح فعالیت / Description» برای نوشتن کار انجام‌شده وجود دارد. متن چندخطی فارسی، آلمانی یا انگلیسی تا ۲۰۰۰ نویسه خودکار همراه همان رکورد ذخیره می‌شود و در پشتیبان و Excel باقی می‌ماند. با انتخاب بلوک زمانی، شرح مربوط در جدول دیده می‌شود؛ توضیح شناور بلوک هم متن را نشان می‌دهد. رکوردهای قدیمی بدون شرح همچنان قابل استفاده‌اند.
- تعطیلات آلمان و آخر هفته‌ها قرمزند. ایالت موردنظر را از فهرست انتخاب کن؛ برخی تعطیلات محلی به محل دقیق وابسته‌اند.
- دکمه‌های `Excel · Jena` و `Excel · Seewiesen` فقط ماه انتخاب‌شده و محل کار مربوط را خروجی می‌دهند. فایل شامل ریز بازه‌ها با ستون `Description / activity` و جمع روزانه با شرح هر بازه است. متن‌ها چندخطی و قابل‌ویرایش‌اند؛ برای شرح‌های بسیار بلند، شیت `Description details` هم اضافه می‌شود تا ادامهٔ متن بدون تغییر در جمع ساعت‌ها خوانا بماند.
- «پشتیبان» یک فایل JSON از همهٔ بازه‌های کاری می‌گیرد. «بازیابی» آن را در نصب دیگر یا نسخهٔ آنلاین وارد می‌کند؛ جایگزینی داده‌های موجود نیاز به تأیید دارد.
- پشتیبان JSON شامل اتصال محرمانه و رویدادهای تقویم نیست. تقویم را در نصب تازه دوباره وصل کن. برای پشتیبان کامل محلی، پس از توقف برنامه از `.data/` هم در جای امن کپی بگیر.
- اجرای محلی و آنلاین دو فضای مستقل هستند. انتقال بین آن‌ها با پشتیبان/بازیابی انجام می‌شود. دستگاه‌هایی که همان آدرس آنلاین را باز می‌کنند، دادهٔ مشترک دارند. حذف، افزودن و ویرایش‌های پشت‌سرهم به‌ترتیب ذخیره می‌شوند؛ تغییرات مستقل صفحه‌ها خودکار ترکیب می‌شوند و شرح فعالیت‌ها حفظ می‌شوند. تغییرات خودت بلافاصله برای ذخیره صف می‌شوند. دریافت خودکار تغییرات دستگاه‌های دیگر در نسخهٔ آنلاین هر ۵ دقیقه هنگام استفاده از صفحه و هنگام بازگشت به آن بررسی می‌شود؛ اجرای محلی فاصلهٔ ۳۰ ثانیه دارد. پس از قطع موقت اتصال، برنامه با فاصله دوباره تلاش می‌کند؛ تا تأیید ذخیره، صفحه را باز نگه دار یا پشتیبان بگیر.
- اگر همان بازه در دو صفحه به‌شکل ناسازگار تغییر کند، برنامه هر دو نسخه را نشان می‌دهد تا نسخهٔ کامل موردنظر را انتخاب کنی. هیچ نسخه‌ای بی‌اطلاع بازنویسی نمی‌شود. در این وضعیت هم می‌توانی پشتیبان بگیری؛ بعد از انتخاب، ذخیره ادامه پیدا می‌کند.

### Google Calendar

در تنظیمات تقویم گوگل، `Integrate calendar → Secret address in iCal format` را کپی و در «اتصال تقویم» وارد کن. لینک فقط در ذخیره‌سازی سمت سرور نگهداری می‌شود و از API به مرورگر برنمی‌گردد. این لینک مانند رمز است؛ آن را در Issue یا کد مخزن ننویس.

هنگام استفاده از نسخهٔ آنلاین، دریافت خودکار فید با فاصلهٔ ۱۵ دقیقه انجام می‌شود؛ در اجرای محلی این فاصله ۶۰ ثانیه است. دکمهٔ تازه‌سازی برای دریافت فوری است. صفحهٔ پنهان یا بدون فعالیت، درخواست مکرر پس‌زمینه نمی‌فرستد. انتشار تغییرات در فید گوگل ممکن است تأخیر داشته باشد؛ این اتصال push یا تضمین بلادرنگ نیست. رویدادهای تقویم به ساعات کار یا اکسل اضافه نمی‌شوند.

## میزبانی خصوصی در Vercel

برای نصب جدید، **Neon Postgres** را به‌عنوان ذخیره‌سازی پایدار پیشنهاد می‌کنیم. اطلاعات کاری، تقویم، نشست‌ها و محدودیت تلاش ورود در پایگاه‌دادهٔ خصوصی سمت سرور نگهداری می‌شوند. کلید ورود برنامه هم لازم است. نبودن تنظیمات لازم باعث بسته ماندن سرویس می‌شود؛ دیسک موقت Vercel جایگزین دادهٔ پایدار نمی‌شود. پشتیبانی از Private Vercel Blob برای نصب‌های قبلی باقی است.

1. مخزن را در Vercel وارد کن، Framework را `Other` و Node.js را `24.x` بگذار. تنظیمات build/install از `vercel.json` خوانده می‌شوند.
2. در تنظیمات پروژه، **Deployment Protection / Vercel Authentication** را برای همهٔ deploymentها از جمله production فعال کن. عمومی بودن کد با دسترسی خصوصی سایت مستقل است. قابلیت‌های حساب و تنظیمات فعلی Vercel را بررسی کن؛ این مرحله را با حفاظت صرفاً preview اشتباه نگیر.
3. از بخش Storage یا [Neon در Vercel Marketplace](https://vercel.com/marketplace/neon)، یک پایگاه‌دادهٔ **جداگانه برای همین برنامه** با طرح **Free** بساز. اتصال را برای محیط‌های موردنیاز، مثل Production و Development، فعال کن. طرح و محدودیت‌های جاری را پیش از ایجاد منبع بررسی کن؛ رایگان بودن به معنی مصرف نامحدود نیست. از پایگاه‌دادهٔ برنامهٔ دیگری استفاده نکن.
4. در Environment Variables سمت سرور، `WORK_PLANNER_MODE=cloud`، `WORK_PLANNER_STORAGE=postgres` و آدرس اتصال در `DATABASE_URL` را تنظیم کن. اگر اتصال Marketplace این متغیر را ساخته، از همان استفاده کن. نام جایگزین `WORK_PLANNER_DATABASE_URL` هم پذیرفته می‌شود و اگر هر دو وجود داشته باشند اولویت دارد. آدرس اتصال شامل رمز است؛ آن را فقط در فایل محیطی خصوصی و تنظیمات سمت سرور نگه دار.
5. پس از `npm ci`، آدرس اتصال را در فایل خصوصی `.env` قرار بده و جدول ذخیره‌سازی را یک بار آماده کن:

```sh
npm run setup:database
npm run setup:key
```

دستور اول تنظیمات `.env` را می‌خواند و ساختار جدول را آماده می‌کند؛ داده‌ای از نصب قبلی وارد نمی‌کند. معادل مستقیم آن `node --env-file=.env scripts/setup-database.mjs` است. دستور دوم یک کلید تصادفی در `.secrets/access-key.txt` و هش آن در `.secrets/cloud.env` می‌سازد. **محتوای هیچ‌کدام را commit نکن.** مقدار `WORK_PLANNER_ACCESS_KEY_HASH` را از فایل دوم در Vercel تنظیم کن. پیشوند `NEXT_PUBLIC_` یا `VITE_` به نام هیچ‌یک از این متغیرها اضافه نکن. کلید واقعی را در password manager نگه دار و فقط در صفحهٔ ورود برنامه وارد کن. هنگام مهاجرت نصب موجود، هش و کلید فعلی را حفظ کن؛ تولید کلید تازه لازم نیست.

6. دوباره deploy کن. ورود ابتدا ممکن است حساب Vercel و سپس کلید برنامه را بخواهد. نشست برنامه هشت ساعت اعتبار دارد؛ خروج آن را باطل می‌کند.

نام محیط (`production`، `preview` یا `development`) به `WORK_PLANNER_STORAGE_PREFIX` اضافه می‌شود؛ مثلاً پیشوند پیش‌فرض به `work-planner-production` تبدیل می‌شود. برای آزمایش اتصال ابری از کامپیوتر خودت، `VERCEL_ENV=development` را هم در محیط همان فرایند تنظیم کن. حالت عادی `WORK_PLANNER_MODE=local` همچنان از فایل‌های محلی استفاده می‌کند و به پایگاه‌داده نیاز ندارد.

برای Preview باید اتصال پایگاه‌داده، انتخاب storage و هش کلید را **در محیط Preview هم صریحاً تنظیم کنی**؛ تنظیم Production به‌تنهایی کافی نیست. پیشوندهای جدا جلوی مخلوط‌شدن اتفاقی اطلاعات را می‌گیرند، اما مرز مجوز پایگاه‌داده نیستند: برای previewهای غیرقابل‌اعتماد از پایگاه‌داده یا branch و اعتبارنامهٔ جدا استفاده کن. اطلاعات محرمانه را در اختیار کد غیرقابل‌اعتماد نگذار. تغییر پیشوند یک فضای تازه باز می‌کند و مهاجرت داده نیست. در استقرار خارج Vercel، HTTPS و یک reverse proxy مورداعتماد لازم است؛ سرور همراه پروژه برای اجرای محلی است.

نصب آنلاین تازه خالی است. برای انتقال، ابتدا پشتیبان نسخهٔ قبلی را بررسی و جداگانه حفظ کن، سپس آن را در نصب جدید «بازیابی» کن و ردیف‌ها، شرح فعالیت‌ها و جمع ساعت‌ها را کنترل کن. تغییر متغیر storage به‌خودی‌خود هیچ داده‌ای منتقل نمی‌کند. تقویم در خروجی JSON نیست و باید دوباره متصل شود یا با روشی امن جداگانه منتقل شود. ورود و دریافت دادهٔ آنلاین به اینترنت نیاز دارد. آدرس پایگاه‌داده و کلید برنامه را عمومی نکن؛ [مدل امنیتی](SECURITY.md) را ببین.

### سازگاری با نصب‌های Blob

برای ادامهٔ استفاده از Blob، `WORK_PLANNER_STORAGE=blob` و یک `BLOB_READ_WRITE_TOKEN` متعلق به store با access برابر **private** را تنظیم کن. برای سازگاری با نصب‌های قبلی، اگر `WORK_PLANNER_STORAGE` در حالت cloud تعیین نشده باشد، Blob انتخاب می‌شود. مقدار `WORK_PLANNER_MODE=cloud` و هش کلید ورود در این حالت هم لازم‌اند.

در حالت Postgres به توکن Blob نیازی نیست، ولی انتخاب Postgres اطلاعات قبلی Blob را حذف یا منتقل نمی‌کند. هنگام مهاجرت، داده‌ها و اعتبارنامهٔ قبلی را تا بررسی کامل نتیجه محفوظ نگه دار. بین دو storage هیچ جایگزینی خودکار هنگام قطعی وجود ندارد.

### اگر فضای ذخیره‌سازی در دسترس نبود

خطای `STORAGE_UNAVAILABLE` یعنی سرویس ذخیره‌سازی پاسخ قابل‌استفاده نداده است؛ این خطا به‌تنهایی به معنی اشتباه بودن کلید نیست. وضعیت سرویس، اتصال پروژه و سهمیهٔ مصرف را در داشبورد **همان provider انتخاب‌شده** بررسی کن. طرح Free در Neon هم محدودیت دارد؛ فضای پایگاه‌داده، مصرف پردازشی و محدودیت‌های جاری را در داشبورد آن کنترل کن و بدون بررسی طرح، ارتقای پولی انجام نده.

در نصب Blob، وجود `BLOB_READ_WRITE_TOKEN` طبیعی و برای اتصال خصوصی سرور ضروری است؛ آن را حذف یا در مخزن منتشر نکن. در طرح Hobby، تمام‌شدن سهمیهٔ عملیات می‌تواند حتی با چند کیلوبایت اطلاعات، خواندن و نوشتن را متوقف کند؛ تعداد درخواست‌ها و دفعات ذخیره هم سهمیه دارند. [محدودیت‌ها و رفتار رسمی Blob](https://vercel.com/docs/vercel-blob/usage-and-pricing#hobby) را ببین. کاهش مصرف برنامه سهمیهٔ مصرف‌شده را برنمی‌گرداند؛ رفع محدودیت فعلی به وضعیت اعلام‌شده در داشبورد وابسته است.

صفحهٔ ورود و `/api/health` بدون خواندن اطلاعات خصوصی باز می‌شوند؛ پاسخ health فقط اجرای برنامه را نشان می‌دهد و تأیید سالم‌بودن ذخیره‌سازی نیست. هنگام قطعی، عملیات وابسته به داده با خطای روشن متوقف می‌شوند، نسخهٔ خالی جایگزین اطلاعات نمی‌شود و تغییرات باز در صفحه نگه داشته می‌شوند. برای جلوگیری از مصرف بیهوده، تلاش خودکار پس از خطای ذخیره‌سازی حداقل ۵ دقیقه فاصله دارد. فایل پشتیبان قدیمی را بدون بررسی تغییرات تازه روی فضای آنلاین بازیابی نکن.

## توسعه و بررسی

```sh
npm test
npm run build
npm run security:scan
npm audit
```

تست‌ها از دادهٔ ساختگی و پوشه‌های موقت استفاده می‌کنند. ذخیرهٔ محلی اتمیک و دارای قفل است. اگر برنامه هنگام نوشتن ناگهان متوقف شد و خطای lock باقی ماند، ابتدا همهٔ پردازش‌های این نصب را ببند، از پوشهٔ داده پشتیبان بگیر و فقط فایل `.json.lock` مربوط را حذف کن؛ فایل داده را حذف نکن.

ساختار اصلی: `public/` رابط، `lib/` ذخیره و ورود، `calendar-service.mjs` تقویم، `export.mjs` اکسل، `server.mjs` اجرای محلی، `api/index.mjs` ورودی Vercel. تمام وابستگی‌های runtime در `package-lock.json` قفل شده‌اند. به Codex یا نرم‌افزار اختصاصی روی کامپیوتر سازنده وابستگی ندارد.

این برنامه ساعت‌های واردشده را ثبت و محاسبه می‌کند؛ تأیید صحت ساعات و فرم‌های رسمی خارج از آن انجام می‌شود. کد پروژه تحت MIT است. کد vendored مربوط به ical.js مجوز جداگانه دارد؛ [اطلاعات و مجوز](vendor/README.md) در مخزن موجود است.
