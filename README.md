# Work Planner

برنامهٔ شخصی ثبت ساعت برای **Jena** و **Seewiesen**: جدول قابل ویرایش، نمای روزانه از ۰۰ تا ۲۴، رسم و جابه‌جایی بازه‌ها، تشخیص هم‌پوشانی و خروجی اکسل جدا برای هر محل کار.

کد این مخزن عمومی است؛ ساعت‌ها، یادداشت‌ها، تقویم و کلیدهای دسترسی داخل مخزن قرار نمی‌گیرند. نصب تازه خالی است. دکمهٔ نمونه فقط دادهٔ آزمایشی مشخص‌شده می‌سازد.

## اجرای محلی روی Windows، macOS یا Linux

پیش‌نیاز: **Node.js 24 LTS** و Git. سپس:

```sh
git clone https://github.com/Raminyazdani/work_planner.git
cd work_planner
npm ci
npm start
```

آدرس [http://127.0.0.1:8765](http://127.0.0.1:8765) را باز کن. پس از نصب اولیه، ویرایش، ذخیره، تشخیص هم‌پوشانی و خروجی اکسل بدون اینترنت کار می‌کنند. دریافت تغییرات Google Calendar به اینترنت نیاز دارد؛ آخرین نسخهٔ دریافت‌شده در اجرای محلی حفظ می‌شود.

برنامهٔ محلی فقط به `127.0.0.1` متصل است. داده‌ها در پوشهٔ خصوصی `.data/` ذخیره می‌شوند. برای تغییر پورت یا محل ذخیره، `.env.example` را به `.env` کپی و ویرایش کن. از قرار دادن `.data/` یا فایل پشتیبان در Git خودداری کن. برای پایان برنامه در ترمینال `Ctrl+C` بزن.

## استفاده و انتقال اطلاعات

- هر ردیف یک بازهٔ کار پیوسته است. استراحت را با دو ردیف جدا ثبت کن؛ گزینهٔ «روز بعد» برای عبور از نیمه‌شب است.
- از جدول یا با کشیدن روی روز موردنظر، بازه بساز. بازه‌ها رنگ جدا دارند و تداخل‌ها مشخص می‌شوند.
- زیر **هر بازه**، کادر «شرح فعالیت / Description» برای نوشتن کار انجام‌شده وجود دارد. متن چندخطی فارسی، آلمانی یا انگلیسی تا ۲۰۰۰ نویسه خودکار همراه همان رکورد ذخیره می‌شود و در پشتیبان و Excel باقی می‌ماند. با انتخاب بلوک زمانی، شرح مربوط در جدول دیده می‌شود؛ توضیح شناور بلوک هم متن را نشان می‌دهد. رکوردهای قدیمی بدون شرح همچنان قابل استفاده‌اند.
- تعطیلات آلمان و آخر هفته‌ها قرمزند. ایالت موردنظر را از فهرست انتخاب کن؛ برخی تعطیلات محلی به محل دقیق وابسته‌اند.
- دکمه‌های `Excel · Jena` و `Excel · Seewiesen` فقط ماه انتخاب‌شده و محل کار مربوط را خروجی می‌دهند. فایل شامل ریز بازه‌ها با ستون `Description / activity` و جمع روزانه با شرح هر بازه است. متن‌ها چندخطی و قابل‌ویرایش‌اند؛ برای شرح‌های بسیار بلند، شیت `Description details` هم اضافه می‌شود تا ادامهٔ متن بدون تغییر در جمع ساعت‌ها خوانا بماند.
- «پشتیبان» یک فایل JSON از همهٔ بازه‌های کاری می‌گیرد. «بازیابی» آن را در نصب دیگر یا نسخهٔ آنلاین وارد می‌کند؛ جایگزینی داده‌های موجود نیاز به تأیید دارد.
- پشتیبان JSON شامل اتصال محرمانه و رویدادهای تقویم نیست. تقویم را در نصب تازه دوباره وصل کن. برای پشتیبان کامل محلی، پس از توقف برنامه از `.data/` هم در جای امن کپی بگیر.
- اجرای محلی و آنلاین دو فضای مستقل هستند. انتقال بین آن‌ها با پشتیبان/بازیابی انجام می‌شود. دستگاه‌هایی که همان آدرس آنلاین را باز می‌کنند، دادهٔ مشترک دارند. حذف، افزودن و ویرایش‌های پشت‌سرهم به‌ترتیب ذخیره می‌شوند؛ تغییرات مستقل صفحه‌ها خودکار ترکیب می‌شوند و شرح فعالیت‌ها حفظ می‌شوند. تغییرات خودت بلافاصله برای ذخیره صف می‌شوند. دریافت خودکار تغییرات دستگاه‌های دیگر در نسخهٔ آنلاین هر ۵ دقیقه هنگام استفاده از صفحه و هنگام بازگشت به آن بررسی می‌شود؛ اجرای محلی فاصلهٔ ۳۰ ثانیه دارد. پس از قطع موقت اتصال، برنامه با فاصله دوباره تلاش می‌کند؛ تا تأیید ذخیره، صفحه را باز نگه دار یا پشتیبان بگیر.
- اگر همان بازه در دو صفحه به‌شکل ناسازگار تغییر کند، برنامه هر دو نسخه را نشان می‌دهد تا نسخهٔ کامل موردنظر را انتخاب کنی. هیچ نسخه‌ای بی‌اطلاع بازنویسی نمی‌شود. در این وضعیت هم می‌توانی پشتیبان بگیری؛ بعد از انتخاب، ذخیره ادامه پیدا می‌کند.

### Google Calendar

در تنظیمات تقویم گوگل، `Integrate calendar → Secret address in iCal format` را کپی و در «اتصال تقویم» وارد کن. لینک فقط در ذخیره‌سازی سمت سرور نگهداری می‌شود و از API به مرورگر برنمی‌گردد. این لینک مانند رمز است؛ آن را در Issue یا کد مخزن ننویس.

هنگام استفاده از نسخهٔ آنلاین، دریافت خودکار فید با فاصلهٔ ۱۵ دقیقه انجام می‌شود؛ در اجرای محلی این فاصله ۶۰ ثانیه است. دکمهٔ تازه‌سازی برای دریافت فوری است. صفحهٔ پنهان یا بدون فعالیت، درخواست مکرر پس‌زمینه نمی‌فرستد. انتشار تغییرات در فید گوگل ممکن است تأخیر داشته باشد؛ این اتصال push یا تضمین بلادرنگ نیست. رویدادهای تقویم به ساعات کار یا اکسل اضافه نمی‌شوند.

## میزبانی خصوصی در Vercel

حالت ابری به **Private Vercel Blob** و **کلید ورود برنامه** نیاز دارد. نبودن تنظیمات لازم باعث بسته ماندن سرویس می‌شود؛ هیچ ذخیرهٔ موقتی روی دیسک Vercel جایگزین دادهٔ پایدار نمی‌شود.

1. مخزن را در Vercel وارد کن، Framework را `Other` و Node.js را `24.x` بگذار. تنظیمات build/install از `vercel.json` خوانده می‌شوند.
2. در تنظیمات پروژه، **Deployment Protection / Vercel Authentication** را برای همهٔ deploymentها از جمله production فعال کن. عمومی بودن کد با دسترسی خصوصی سایت مستقل است. قابلیت‌های حساب و تنظیمات فعلی Vercel را بررسی کن؛ این مرحله را با حفاظت صرفاً preview اشتباه نگیر.
3. یک Blob store با access برابر **private** بساز و به محیط‌های لازم متصل کن. متغیر `BLOB_READ_WRITE_TOKEN` باید در همان محیط‌ها موجود باشد. برای این کار CLI هم قابل استفاده است:

```sh
npx vercel login
npx vercel link
npx vercel blob create-store work-planner-private --access private --region fra1 --yes
npm run setup:key
```

4. دستور آخر یک کلید تصادفی در `.secrets/access-key.txt` و هش آن در `.secrets/cloud.env` می‌سازد. **محتوای هیچ‌کدام را commit نکن.** در Environment Variables سمت سرور Vercel مقدارهای `WORK_PLANNER_MODE=cloud` و `WORK_PLANNER_ACCESS_KEY_HASH` را از فایل دوم تنظیم کن. پیشوند `NEXT_PUBLIC_` یا `VITE_` اضافه نکن. کلید واقعی را در password manager نگه دار و فقط در صفحهٔ ورود برنامه وارد کن.
5. دوباره deploy کن. ورود ابتدا ممکن است حساب Vercel و سپس کلید برنامه را بخواهد. نشست برنامه هشت ساعت اعتبار دارد؛ خروج آن را باطل می‌کند.

داده‌ها، تقویم، نشست‌ها و محدودیت تلاش ورود در Private Blob ذخیره می‌شوند. نام محیط (`production`، `preview` یا `development`) به پیشوند ذخیره اضافه می‌شود تا preview دادهٔ production را تغییر ندهد. در صورت نیاز `WORK_PLANNER_STORAGE_PREFIX` را تغییر بده؛ این کار یک فضای دادهٔ جدید باز می‌کند و مهاجرت داده نیست. در استقرار خارج Vercel، HTTPS و یک reverse proxy مورداعتماد لازم است؛ سرور همراه پروژه برای اجرای محلی است.

نصب آنلاین تازه خالی است؛ از نسخهٔ قبلی «پشتیبان» بگیر و در آن «بازیابی» کن. ورود و دریافت دادهٔ آنلاین به اینترنت نیاز دارد. کلید Blob و کلید برنامه را عمومی نکن؛ [مدل امنیتی](SECURITY.md) را ببین.

### اگر فضای ذخیره‌سازی در دسترس نبود

`BLOB_READ_WRITE_TOKEN` کلید اتصال خصوصی سرور به Blob است و وجودش طبیعی و ضروری است. آن را حذف یا در مخزن منتشر نکن.

خطای `STORAGE_UNAVAILABLE` یعنی سرویس ذخیره‌سازی پاسخ قابل‌استفاده نداده است؛ این خطا به‌تنهایی به معنی اشتباه بودن کلید نیست. وضعیت Blob و بخش Usage در داشبورد Vercel را بررسی کن. در طرح Hobby، تمام‌شدن سهمیهٔ عملیات می‌تواند حتی با چند کیلوبایت اطلاعات، خواندن و نوشتن را متوقف کند؛ تعداد درخواست‌ها و دفعات ذخیره هم سهمیه دارند. [محدودیت‌ها و رفتار رسمی Blob](https://vercel.com/docs/vercel-blob/usage-and-pricing#hobby) را ببین. کاهش مصرف برنامه سهمیهٔ مصرف‌شده را برنمی‌گرداند؛ رفع محدودیت فعلی به زمان اعلام‌شده در داشبورد یا تغییر طرح حساب وابسته است.

صفحهٔ ورود و `/api/health` بدون خواندن اطلاعات خصوصی باز می‌شوند؛ پاسخ health فقط اجرای برنامه را نشان می‌دهد و تأیید سالم‌بودن Blob نیست. هنگام قطعی، عملیات وابسته به داده با خطای روشن متوقف می‌شوند، نسخهٔ خالی جایگزین اطلاعات نمی‌شود و تغییرات باز در صفحه نگه داشته می‌شوند. برای جلوگیری از مصرف بیهوده، تلاش خودکار پس از خطای ذخیره‌سازی حداقل ۵ دقیقه فاصله دارد. فایل پشتیبان قدیمی را بدون بررسی تغییرات تازه روی فضای آنلاین بازیابی نکن.

## توسعه و بررسی

```sh
npm test
npm run build
npm run security:scan
npm audit
```

تست‌ها از دادهٔ ساختگی و پوشه‌های موقت استفاده می‌کنند. ذخیرهٔ محلی اتمیک و دارای قفل است. اگر برنامه هنگام نوشتن ناگهان متوقف شد و خطای lock باقی ماند، ابتدا همهٔ پردازش‌های این نصب را ببند، از پوشهٔ داده پشتیبان بگیر و فقط فایل `.json.lock` مربوط را حذف کن؛ فایل داده را حذف نکن.

ساختار اصلی: `public/` رابط، `lib/` ذخیره و ورود، `calendar-service.mjs` تقویم، `export.mjs` اکسل، `server.mjs` اجرای محلی، `api/index.mjs` ورودی Vercel. تمام وابستگی‌های runtime در `package-lock.json` قفل شده‌اند. به Codex یا نرم‌افزار اختصاصی روی کامپیوتر سازنده وابستگی ندارد.

این برنامه ساعت‌های واردشده را ثبت و محاسبه می‌کند؛ تأیید صحت ساعات و فرم‌های رسمی خارج از آن انجام می‌شود. کد پروژه تحت MIT است. کد vendored مربوط به ical.js مجوز جداگانه دارد؛ [اطلاعات و مجوز](vendor/README.md) در مخزن موجود است.
